# 散热器控制规格（待实装）

本文是第二块继电器（GPIO8）散热器功能的当前权威设计。现阶段只冻结逻辑和待测参数，不表示正式固件已经启用散热器自动控制。

## 1. 已确认的散热器行为

- 散热器有四个离散档位：`LEVEL_1` 最低，`LEVEL_4` 最高。
- 实体按钮单击：升一档；`LEVEL_4` 再单击会循环回 `LEVEL_1`。
- 实体按钮双击：降一档；`LEVEL_1` 再双击保持 `LEVEL_1`。
- 实体按钮长按：关机。
- 关机状态下单击：开机。
- 关机会记忆关机前档位，下次开机恢复该档位。
- 已实测 GPIO8 第二块继电器能够模拟散热器按钮，但双击识别窗口较严格。

## 2. 控制模式

模式按以下顺序循环：

```text
MANUAL -> STANDARD -> SILENT -> TURBO -> MANUAL
```

| 模式 | 控制方式 | 默认目标温度 |
|---|---|---:|
| Manual | 用户直接控制档位 | 不使用目标温度 |
| Standard | ESP32 根据当前主机 CPU 温度自动调档 | 40°C |
| Silent | ESP32 根据当前主机 CPU 温度自动调档 | 50°C |
| Turbo | ESP32 根据当前主机 CPU 温度自动调档 | 28°C |

- 自动模式的目标温度是可调状态，不能写死在控制算法中；表中数值只是每种模式的默认值。
- 各模式的当前目标温度与当前模式应写入 NVS，重启后恢复。
- 只有当前 KVM 主机的新鲜、有效 CPU 温度可以参与控制；非当前主机数据不得参与。

## 3. 第三个按钮

按键扫描只发布语义事件，必须等到能够排除更长按压后才执行较短按压动作。

### Manual 模式

- 单击：散热器升一档。
- 双击：散热器降一档。
- 持续按住达到 500ms、并在 1000ms 前松开：松开时切换到下一种模式。
- 持续按住达到 1000ms：不等待松开，立即发送散热器关机长按；松开时不得再切换模式。

### Standard、Silent、Turbo 模式

- 单击：将当前模式目标温度提高 `1°C`；双击：降低 `1°C`，不直接改变档位。首轮允许范围为 `20–70°C`，这些参数集中配置，实测后可调整。
- 500–999ms 后松开：切换到下一种模式。
- 按住达到 1000ms：立即关机，松开时不得切换模式。

目标温度调节方向、步长和范围是 dev.11 为完成实装采用的临时规则，不视为最终人体工学结论。

> 解释：此前“约500ms长按切模式”的要求按 `500ms <= 按住时间 < 1000ms` 理解。少于500ms仍需留给单击/双击识别，否则会与手动档位或目标温度调整冲突。

## 4. 继电器按键时序

第一轮实测基准参数：

```text
单击：闭合 120ms，然后释放

双击：闭合 70ms -> 释放 80ms -> 闭合 70ms -> 释放

连续两组双击：组间等待 1000ms
```

- 参数必须集中配置，不得散落在页面或业务代码中。
- 单击和双击脉冲分别配置：单击为120ms，双击内部仍为70ms，避免延长单击时破坏已经可用的双击窗口。
- 双击必须先单独实测：降一档表示成功；升两档表示中间释放过长；无响应表示闭合过短。
- 机械继电器的常见吸合/释放时间足以覆盖这一时序，但最终值以本机散热器实测为准。
- 散热器关机继电器闭合时间在 dev.11 调整为 2000ms；第三按钮按住达到 1 秒时即开始执行该动作，用户不需要继续按住到 2 秒。

## 5. 上电校准与状态

因为散热器没有档位反馈，ESP32上电后通过以下流程将未知档位归一到一档：

```text
等待散热器控制器启动稳定（初值 1–2 秒，待实测）
-> 模拟长按，确保关机
-> 等待按键处理完成
-> 单击，确保开机
-> 连续发送三组有效双击，组间留足处理时间
-> 将推定状态设为 LEVEL_1
```

三组降档对任意记忆档位都收敛到一档。该流程只能在 ESP32/散热器上电、用户主动重新校准或状态变为 `UNKNOWN` 时运行，不得因 Wi-Fi 重连、客户端上下线或 UI 刷新重复执行。

状态模型：

```text
UNKNOWN
INITIALIZING
OFF
LEVEL_1
LEVEL_2
LEVEL_3
LEVEL_4
ERROR
```

档位属于推定状态。人工按散热器实体按钮、继电器漏脉冲或散热器漏识别都会造成状态漂移，必须提供“重新校准”入口。

## 6. 自动控温算法

散热器只有四档且没有转速/档位反馈，不采用连续 PID。采用带回差、持续确认和最短保持时间的离散分档控制。

### 输入处理

1. 每秒接收当前主机 CPU 温度。
2. 丢弃无效值和过期值。
3. 使用约 10–15 秒的指数平滑温度作为控制温度；原始温度只用于过热保护。
4. 保存最近一段时间的温度趋势，用于区分短促尖峰和持续升温。

### 正常调档

- 控制死区初值为目标温度上下 `2°C`。
- 平滑温度处于 `目标温度 - 2°C` 到 `目标温度 + 2°C` 时保持当前档位。
- 高于上边界并持续约 10 秒：只升一档。
- 低于下边界并持续约 30 秒：只降一档。
- 每次升档后至少保持约 45–60 秒；每次降档后至少保持约 60–90 秒，再允许下一次普通调档。
- 温度继续快速上升时可以缩短升档确认时间，但一次仍只改变一档。
- `LEVEL_4` 禁止继续发送单击，避免循环回 `LEVEL_1`；`LEVEL_1` 禁止继续发送降档双击。

以上温差和时间均为首轮调试值，必须集中配置并通过实机温度曲线调整。

### 保护与降级

- 原始温度超过待确认的过热阈值时，跳过普通保持时间，逐级提升到 `LEVEL_4`；过热阈值未确认前不得自行发明固定数值。
- 当前主机离线、温度无效/过期、散热器状态未知或继电器正在执行动作时，暂停自动调档。
- 自动模式不会因一次瞬时尖峰连续跨越多个档位。
- 模式切换后保留散热器当前档位，重新开始持续时间和保持时间计数，不立即连发按键。
- 用户关机后进入 `OFF`，自动控制必须停止；是否由温度自动重新开机尚未确认，当前设计不得自行开机。

## 7. 尚待确认或实测

1. 双击 `70ms / 80ms / 70ms` 是否在本机上稳定识别。
2. 两组双击之间 1000ms 是否足够。
3. 散热器可靠关机所需的继电器闭合时长。
4. 通电后开始校准所需等待时间，以及开机单击后的等待时间。
5. `1°C`步长和`20–70°C`范围是否符合实际操作习惯。
6. 过热保护温度。
7. 自动模式关机后是否允许因高温自动重新开机。
8. 三种自动模式是否还需要限制最高档位；当前仅用不同目标温度区分。
