# 双主机显示器待机与唤醒计划

状态：ESP32 `v0.5.0-dev.22`与Mac客户端已实装；Windows升级指南已冻结，等待Windows客户端实现与三端实机验收。

## 1. 已确认的 X41Q 行为

- Mac执行系统显示休眠后，Mac停止视频输出，X41Q进入黑屏待机；恢复Mac活动后，显示器能够重新亮屏。
- 向X41Q写入DDC VCP `0xD6 = 4`时，显示器会短暂黑屏。
- 如果Windows的DP仍有有效视频信号，X41Q会自动切换到DP，不会保持待机。
- 拔掉Windows DP后，当所有输入均无有效信号，X41Q进入电源灯闪烁的待机状态。
- 因此，系统应控制两台主机停止/恢复视频输出，而不是依赖单独的DDC关机命令维持待机。

## 2. 进入待机

```text
用户长按ESP32左键
-> ESP32关闭自身LCD背光
-> ESP32确认Mac和Windows客户端均在线
-> 向两台客户端发送唯一request_id的display_sleep命令
-> Mac停止显示输出
-> Windows停止显示输出
-> 分别等待执行结果
-> 两台均成功后，X41Q因无有效输入自然进入待机
```

- 两条命令应并行发送，不能先关闭当前主机后永久失去操作反馈。
- ESP32背光关闭与双主机休眠属于同一个用户动作；即使某台客户端失败，ESP32背光仍保持关闭，但内部必须保存失败原因，唤醒后显示。
- 任意一台离线、拒绝、失败或超时，都不得显示“待机成功”；UI应指出未停止输出的主机。
- 电脑本身继续运行，WebSocket客户端、下载、计算和后台任务不得因此暂停。
- `DDC 0xD6 = 4`不作为必要步骤；它可以保留为实验性辅助，但不能作为成功依据。

## 3. 唤醒

```text
ESP32背光关闭时用户再次长按左键
-> ESP32恢复自身LCD背光
-> 读取关屏前保存的当前显示目标
-> ESP32只向该目标客户端发送display_wake
-> 目标主机恢复视频输出
-> X41Q检测到唯一有效信号并退出待机
-> 等待画面稳定
-> 更新显示目标与状态
```

- 唤醒阶段先只恢复目标主机，禁止同时恢复两台，以免X41Q自动选错输入。
- Mac和Windows电脑本身没有进入系统睡眠，客户端仍在运行，因此理论上可以自动恢复显示输出，不要求用户手动操作；两端的唤醒API仍必须分别实测。
- 默认不同时唤醒两台电脑输出。若以后需要恢复非目标主机，必须在目标画面稳定和输入归属明确后执行，且不能导致X41Q自动抢源。
- 如果电脑实际进入了整机睡眠而非仅关闭显示输出，普通WebSocket客户端无法接收唤醒命令；此情况需要键鼠或Wake-on-LAN，不属于本阶段功能。
- 目标画面稳定后，是否恢复非目标主机输出必须通过实测决定；默认保持非目标主机显示输出休眠。
- 如果系统能够在待机状态下可靠执行DDC输入选择，可以在目标信号恢复后追加`0x60`校正；未验证前不得依赖它完成唤醒。
- 目标客户端离线时拒绝唤醒请求，并保留实体显示器电源键和主机键鼠作为人工恢复路径。

## 4. 客户端职责

### macOS

- `display_sleep`执行系统显示休眠，效果等同已验证的`pmset displaysleepnow`，但正式实现优先使用合适的系统API/受控子进程并返回真实结果。
- `display_wake`触发用户活动/显示唤醒；具体API必须实测，不能仅以函数调用返回值判定画面已恢复。
- 只关闭显示输出，不让Mac整机进入睡眠。

### Windows

- `display_sleep`使用Windows显示器电源接口停止显示输出，不关闭、休眠或挂起台式机。
- `display_wake`恢复显示输出；必须在目标Windows版本上验证系统API和显卡驱动行为。
- 托盘客户端在显示输出关闭期间继续联网和上报遥测。

## 5. ESP32黑屏输入锁定

- ESP32 LCD背光关闭后进入`DISPLAY_SLEEP_LOCKED`状态。
- 该状态下只接受“左键长按”作为唤醒动作。
- 左键单击、左键双击、中键全部动作、右键全部动作一律丢弃，不排队、不延后执行，也不得触发DDC、USB继电器、散热器或模式变化。
- 进入锁定时必须清除已经等待判定的单击/双击及事件队列，防止关屏前的残留点击在关屏后执行。
- 唤醒所用的左键长按释放后不得再产生单击或双击事件。
- 恢复背光并退出锁定后，普通按键功能才重新开放。

## 6. 协议实现

protocol v1通过Hello中的可选`capabilities`做兼容扩展，新增：

- `display_sleep`
- `display_wake`

每个命令继续携带`protocol_version`、唯一`request_id`与`target_device_id`，客户端必须去重并返回`command_result`。结果至少区分：

- 命令已接受；
- 系统调用成功；
- 系统调用失败；
- 客户端离线；
- 超时；
- 另一台主机未能停止输出，无法确认显示器待机。

未声明能力的旧客户端仍可连接并使用既有遥测与KVM功能；ESP32不得向其发送休眠/唤醒命令。完整报文和结果字段以`../../../StatsForKVM/PROTOCOL.md`及`../../../Windows/WINDOWS_DISPLAY_POWER_UPGRADE.md`为准。

## 7. 当前开发版验收

1. Mac、Windows同时在线时，连续20次进入待机，X41Q均进入电源灯闪烁状态。
2. 分别以Mac和Windows为目标各唤醒10次，X41Q显示正确主机。
3. 待机期间两台客户端持续在线并上报遥测，电脑后台任务不中断。
4. 任一客户端离线时不得误报成功，UI明确显示失败主机。
5. 唤醒时不出现两台视频源争抢或自动跳错输入。
6. 实体键鼠和显示器电源键始终能够人工恢复。
7. ESP32黑屏期间反复单击/双击三个按键均不产生任何业务动作，只有左键长按能够恢复。
