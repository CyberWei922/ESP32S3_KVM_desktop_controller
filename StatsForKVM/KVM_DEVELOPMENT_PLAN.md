# StatsForKVM 后续开发规划

## 1. 文档目的

本文档记录 StatsForKVM 在原版 Stats 基础上增加 ESP32 数据传输和显示器切换功能的技术路线、功能边界、开发顺序与验收标准。

除本文档明确列出的扩展外，Stats 原有的系统数据采集、菜单栏显示、模块设置和其他功能原则上保持不变。开发时优先采用低侵入方式，减少对原项目结构的修改。

只有经过实际构建和本机运行验证后，才能标记为完成。当前代码状态与验证证据分别记录在 `VERSION.md` 和 `VERIFICATION.md`；本文件未明确标记的内容仍按规划项处理。

## 2. 页面命名与职责

在 Stats 设置窗口左侧栏新增两个独立页面，并沿用原软件的界面布局、控件样式、间距和交互规范。

### 2.1 监视器（Monitor）

负责从 Stats 已有数据源取得监测数据，并通过局域网发送给 ESP32。

职责包括：

- 启用或关闭数据传输。
- 配置 ESP32 的网络地址和连接参数。
- 显示 WebSocket 连接、断线和重连状态。
- 显示最近一次成功发送时间及明确的错误信息。
- 提供连接测试和当前 JSON 数据预览。
- 后续提供类似 Stats 传感器页面的逐项勾选功能，让用户选择 ESP32 屏幕显示的数据。

基础 telemetry 仍传输以下两个数值：

1. CPU 温度：对应 Stats 传感器数据中的 `Average CPU`，单位为摄氏度。
2. 内存占用百分比：复用 Stats 当前 RAM 模块的占用率计算结果。

首版不传输 CPU 使用率、单核心温度、磁盘、网络、GPU 或其他传感器数据。

当前开发版另外发送独立的 `dashboard` 快照，内容包括天气、未来预报、BTC/USDT、DOGE/USDT 和 USD/CNY。Windows 是主数据源，macOS 是备用数据源；ESP32 只负责校验、缓存和显示。

### 2.2 KVM

负责外接显示器输入源切换，不负责监测数据传输。

职责包括：

- 启用或关闭显示器控制。
- 发现并选择目标外接显示器。
- 保存目标显示器的稳定标识。
- 配置 Mac 和 Windows 分别对应的显示器输入源。
- 提供手动切换到 Mac、切换到 Windows的测试按钮。
- 显示最近一次操作、执行结果和明确的失败原因。
- 后续接收 ESP32 通过 WebSocket 下发的显示器切换命令。
- 接收 ESP32 下发的 `display_sleep` 和 `display_wake` 命令，只停止或恢复显示输出，不让 Mac 进入整机睡眠。

## 3. 总体结构

```text
Stats 原有数据采集模块
├── 原有菜单栏、弹窗和设置页面
└── StatsForKVM 数据分流
    └── Monitor 数据中心
        └── JSON 编码
            └── WebSocket 客户端
                └── ESP32 WebSocket 服务器

ESP32 显示器切换命令
└── StatsForKVM WebSocket 客户端
    └── KVM 命令校验
        └── DisplayController
            └── 内置 m1ddc 底层代码
                └── 外接显示器 DDC/CI
```

Monitor 和 KVM 共用同一个 WebSocket 连接，但保持独立的业务逻辑、状态和设置页面。

## 4. 数据采集路线

### 4.1 基本原则

- 不从菜单栏文字或界面反向读取数据。
- 不为 Monitor 重复创建 CPU、RAM 或传感器 Reader。
- 在 Stats 原有 Reader 得到数据后的回调处，将最新结果额外分流给 Monitor 数据中心。
- 原有 Stats 显示逻辑继续使用同一份采集结果。
- Monitor 关闭时停止 JSON 编码和网络发送，尽量不增加后台负担。

### 4.2 首版 CPU 温度

- 指标 ID：`cpu.temperature.average`
- 数据来源：Stats Sensors 模块中的 `Average CPU`。
- 单位：`celsius`。
- 必须同时记录数值有效性和传感器来源。
- 无法取得温度时，数值必须为 `null`，不得使用 `0` 代替。
- 失败时必须带有稳定的错误代码或可读错误原因。

### 4.3 首版内存占用

- 指标 ID：`memory.usage`
- 数据来源：Stats RAM 模块现有 `RAM_Usage` 结果。
- 单位：`percent`。
- 使用 Stats 当前的内存占用语义和计算方式，保证菜单栏与 ESP32 数据一致。
- 数据不可用时必须标记为无效，不发送伪造的零值。

### 4.4 后续指标选择

后续建立统一的指标注册表。每项指标至少包含：

- 稳定的指标 ID。
- 中英文名称。
- 当前数值和单位。
- 是否有效。
- 数据来源。
- 错误原因。
- 是否发送到 ESP32。

Monitor 页面后续可按 CPU、内存、温度、网络、磁盘等分类显示开关，交互方式参考 Stats 现有传感器勾选列表。首版只显示并启用已经确定的两个指标。

## 5. JSON 数据协议

协议从首版开始包含版本号、设备身份、消息序号和有效状态，以便将来扩展而不破坏 ESP32 端兼容性。

示例：

```json
{
  "type": "telemetry",
  "protocol_version": 1,
  "device_id": "macbook-air-m5",
  "platform": "macos",
  "sequence": 1,
  "timestamp_ms": 1788796800000,
  "metrics": {
    "cpu.temperature.average": {
      "value": 48.2,
      "unit": "celsius",
      "valid": true,
      "source": "Average CPU",
      "error": null
    },
    "memory.usage": {
      "value": 51.3,
      "unit": "percent",
      "valid": true,
      "source": "Stats RAM_Usage",
      "error": null
    }
  }
}
```

CPU 温度不可用时示例：

```json
{
  "value": null,
  "unit": "celsius",
  "valid": false,
  "source": "Average CPU",
  "error": "sensor_unavailable"
}
```

具体字段长度和最终消息大小需要在 ESP32 上实测后确定，未经实测不得标记协议完成。

## 6. WebSocket 网络路线

### 6.1 连接方向

ESP32 作为 WebSocket 服务器，Mac 和 Windows 分别作为 WebSocket 客户端主动连接 ESP32。

```text
StatsForKVM（Mac） ─────┐
                       ├── ESP32 WebSocket 服务器
Windows 监控程序 ───────┘
```

这样可以避免在 Mac 和 Windows 上开放入站服务器端口，也便于 ESP32 在同一连接上向指定电脑返回消息或发送控制命令。

### 6.2 多客户端要求

- ESP32 必须允许 Mac 和 Windows 同时连接。
- 每个客户端连接后首先发送 `hello` 身份消息。
- 身份信息至少包含协议版本、设备 ID、平台和应用名称。
- ESP32 按设备 ID 分别保存两台电脑的最新数据和在线状态。
- 遥测数据只保存最新快照，不在内存中无限积累历史记录。
- 客户端断开后，ESP32 应将对应设备标记为离线。
- 初始发送频率建议为每秒一次，最终频率以实机稳定性测试为准。
- ESP32 应限制最大连接数、单条消息长度和允许的命令类型。

### 6.3 StatsForKVM 客户端要求

- 自动连接和断线重连。
- 心跳与超时检测。
- 应用休眠、唤醒及网络变化后的恢复。
- 界面显示连接中、已连接、已断开和错误状态。
- 网络处理不得阻塞 Stats 主线程和原有采集模块。
- UI 不直接操作 WebSocket，由独立传输服务负责。

### 6.4 VPN、系统代理和虚拟网卡兼容要求

用户可能长期启用 VPN、系统代理、代理自动配置脚本以及由虚拟机、容器或代理软件创建的虚拟网卡。WebSocket 实现不能只在未启用这些工具的普通网络环境中验证。

- 优先使用 Apple `Network.framework` 建立直连 ESP32 的 WebSocket，不依赖系统 HTTP 代理完成局域网通信。
- ESP32 使用路由器 DHCP 地址保留获得稳定局域网 IP；Bonjour 名称只作为辅助发现和地址恢复手段，不能作为唯一连接方式。
- 监听网络路径变化。Wi-Fi 切换、VPN 开关、休眠唤醒或网络接口变化后，应关闭失效连接并重新建立连接。
- 开发时记录连接实际采用的网络路径和接口，避免仅根据系统显示的“网络已连接”判断 ESP32 可达。
- 研究并实现“自动选择网络”和“优先使用物理 Wi-Fi/LAN”两种连接策略的可行性。
- 不尝试绕过 VPN 软件明确设置的本地网络访问限制；此时应提示用户在 VPN 中启用 `Allow LAN traffic`、`Bypass local network` 或同类选项。
- 检测并报告 VPN 网段与本地局域网网段重叠导致的路由冲突。
- Monitor 页面应尽可能区分 ESP32 不可达、局域网不可用、VPN 可能阻止访问、网段冲突、WebSocket 握手失败和普通断线等状态。
- 不得在断线期间无限累计待发送遥测。恢复连接后直接发送最新数据快照。

连接地址的建议尝试顺序：

```text
已保存的 ESP32 固定局域网 IP
→ Bonjour 辅助重新发现
→ 提示用户重新选择或填写 ESP32 地址
```

## 7. m1ddc 源码集成路线

### 7.1 决策

不以外部命令行程序方式调用 m1ddc。将所需底层源码直接集成进 StatsForKVM，并固定使用经过实机验证的版本。

m1ddc 采用 MIT 许可证。集成时必须保留其原始 LICENSE、版权声明、上游项目地址和所采用的 Git 提交号。

### 7.2 建议目录

```text
StatsForKVM/
├── ThirdParty/
│   └── m1ddc/
│       ├── Sources/
│       ├── Headers/
│       ├── LICENSE
│       └── UPSTREAM.md
└── Stats/
    └── KVM/
        ├── KVMSettingsView.swift
        ├── DisplayController.swift
        └── M1DDCBridge.swift
```

最终目录可依据现有 Xcode Target 和模块依赖做小幅调整，但第三方源码必须与 StatsForKVM 自有代码清晰分离。

### 7.3 集成边界

只集成显示器控制需要的部分：

- 显示器发现。
- 显示器稳定标识读取。
- DDC/CI 读写。
- VCP 输入源切换。
- 当前开发版显示待机：响应ESP32的`display_sleep`，只停止Mac显示输出而不让整机睡眠；响应`display_wake`恢复输出。与Windows端及ESP32的完整联动规则见`../esp32/latest/docs/display_sleep_plan.md`。

不集成 m1ddc 的命令行参数解析和终端输出层。

使用 Objective-C 包装层向 Swift 暴露小型、稳定接口。Swift 的 `DisplayController` 负责业务逻辑，KVM 页面不得直接调用 m1ddc 的底层全局函数。

所有 DDC 操作放到后台串行队列中，防止阻塞界面或同时发送互相冲突的切换命令。

### 7.4 实机验证要求

在实现自动控制前，必须先在当前 Mac 和目标显示器上确认：

- [x] 能否发现目标显示器。
- 哪个标识在重启和重新插拔后保持稳定。
- [x] 当前连接方式是否透传 DDC/CI；新 USB-C→HDMI 转接器已确认支持写入。
- [x] Mac、Windows 分别对应的输入源编号；X41Q 为 DP=`7`、HDMI1=`5`、HDMI2=`6`。
- 连续切换是否稳定。
- 是否需要管理员权限。
- macOS 27 开发版升级可能带来的私有接口兼容风险。

以上内容必须基于实际测试记录，不能仅根据 m1ddc 文档标记完成。

## 8. KVM 命令安全边界

- 只接受协议中定义的命令类型。
- 只允许切换到 KVM 页面预先保存的目标显示器。
- 只允许使用预先配置的 Mac 和 Windows 输入源。
- 无效设备 ID、未知输入源或超长消息必须拒绝。
- 同一时间只执行一个显示器切换命令。
- 每次操作向 ESP32 返回成功或明确的错误结果。
- 首版仅在可信局域网内使用；是否增加配对令牌在联调阶段决定。

## 9. 实现顺序

### 阶段 1：页面和数据结构

1. 在设置侧栏增加“监视器（Monitor）”和“KVM”两个页面骨架。
2. 沿用 Stats 现有 AppKit 设置页面样式，不改造整个设置窗口。
3. 建立 Monitor 指标模型、最新数据快照和有效状态定义。
4. 建立 KVM 页面配置模型，但暂不执行显示器切换。

### 阶段 2：首版本机数据分流

1. 从 Sensors 的 `Average CPU` 原始结果分流 CPU 温度。
2. 从 RAM 模块原始结果分流内存占用百分比。
3. 保证 Stats 原有菜单栏和设置功能不受影响。
4. 验证温度不可用时输出 `null`、无效状态和错误原因。
5. 连续输出首版 JSON，并在本机验证稳定性和资源占用。

### 阶段 3：Monitor 网络功能

1. 建立与 UI 分离的 WebSocket 客户端服务。
2. 实现身份消息、遥测消息、序号、心跳和断线重连。
3. 实现网络路径监听、固定 IP 连接和 Bonjour 辅助发现。
4. 在本机模拟 WebSocket 服务上验证。
5. 分别在关闭和开启常用 VPN、系统代理及虚拟网卡的状态下验证。
6. 在 ESP32 上实现同时接受 Mac 和 Windows 的多客户端服务。
7. 实机验证持续运行、网络切换、断线恢复和 ESP32 内存占用。

### 阶段 4：m1ddc 底层验证与集成

1. 固定 m1ddc 上游提交并记录许可证信息。
2. 在当前 Mac、显示器和连接方式上独立验证 DDC/CI。（写入与实际切换已验证，读回仍异常。）
3. 确认显示器标识和输入源编号。（当前标识 `12547`；输入值 DP=`7`、HDMI1=`5`、HDMI2=`6`。）
4. 导入需要的 m1ddc 底层源码。
5. 建立 Objective-C 包装层和 Swift `DisplayController`。
6. 完成代码签名、构建和运行验证。

### 阶段 5：KVM 页面与远程命令

1. 实现目标显示器和输入源配置。
2. 实现手动切换到 Mac 和 Windows。
3. 展示最近操作和错误原因。
4. 定义 ESP32 下发的显示器切换命令。
5. 通过已有 WebSocket 连接接收、校验并执行命令。
6. 将执行结果返回 ESP32。

### 阶段 6：后续扩展

1. 在 Monitor 页面增加类似传感器页面的逐项勾选列表。
2. 扩展可发送指标，但不破坏协议版本 1 的兼容性。
3. 根据 ESP32 屏幕布局增加显示位置配置。
4. 完成登录自启和长期运行测试。
5. 为 StatsForKVM 建立独立更新策略，避免使用原版 Stats 更新覆盖修改版。

## 10. 首版验收标准

首版 Monitor 只有在满足以下条件后才能标记完成：

- Stats 原有功能可以正常构建和运行。
- Monitor 页面能启用和关闭传输。
- 数据仅包含 `Average CPU` 温度和内存占用百分比。
- 两项数据均来自 Stats 原有采集结果，没有重复 Reader。
- CPU 温度不可用时不输出 `0°C`。
- JSON 格式稳定，并带有协议版本、设备身份、时间和有效状态。
- WebSocket 断开不会导致 StatsForKVM 崩溃或阻塞。
- ESP32 可以同时保持 Mac 和 Windows 两个客户端连接。
- 开启常用系统代理后，StatsForKVM 仍可直连局域网内的 ESP32，或者能够显示明确的阻断原因。
- 开启和关闭常用 VPN、切换 Wi-Fi、出现虚拟网卡以及休眠唤醒后，连接恢复行为已经实测并记录。
- VPN 禁止局域网访问或发生网段冲突时，Monitor 页面能够提供明确提示，不将其误报为 ESP32 故障。
- 断线期间不会无限堆积历史遥测消息，恢复后发送最新快照。
- 实际连续运行测试结果已记录。

首版 KVM 只有在满足以下条件后才能标记完成：

- m1ddc 底层源码和许可证信息已清晰隔离并记录。
- 当前目标显示器可以被稳定识别。
- 可以从 KVM 页面手动切换到 Mac 和 Windows 输入源。
- 失败时显示明确原因，不把失败操作报告为成功。
- ESP32 可以向指定 Mac 客户端下发命令并收到执行结果。

## 11. 暂不包含的工作

- 本阶段不修改 ESP32 当前冻结固件，直到 Mac 端本地采集和协议验证完成。
- Windows 客户端源码在独立 Windows 主机上开发；当前公开仓库暂不包含 Windows 目录，待 Windows 实现稳定后再同步源码。
- 暂不处理 3D 打印外壳。
- 暂不增加首版范围之外的监控数据。
- 暂不对未在当前设备上实测的功能作完成标记。
