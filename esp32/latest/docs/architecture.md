# v0.5.0-dev.22 软件架构

## 目标

新版采用分层架构，将LVGL、状态、网络、按钮和继电器解耦。UI只是状态的展示者和用户事件入口，不能直接拥有网络连接或执行长时间硬件时序。

```text
Mac App ─┐
         ├─ WebSocket/protocol v1 ─ 网络服务 ─┐
Win App ─┘                                    │
                                              ├─ 线程安全状态仓库 ─ UI消息 ─ LVGL任务
三个按钮 ─ 按键扫描/消抖 ─ 语义事件队列 ─────┤
                                              ├─ KVM状态机 ─ USB继电器
Mac温度 ──────────────────────────────────────└─ 温控状态机 ─ 散热器继电器
```

## 任务边界

- LVGL任务：唯一允许调用LVGL API的任务，处理页面、组件和局部刷新。
- 网络任务：连接、解析、校验和更新最新状态，不直接绘图。
- 按键任务：采样、消抖、单击/双击/长按识别，只发布语义事件。
- KVM状态机：在线检查、DDC请求、超时、USB脉冲、冷却和校准。
- 温控状态机：平滑温度、选择目标档位并顺序产生继电器时序。
- 维护任务：数据过期、连接超时、看门狗和安全释放。

## 状态原则

- Mac和Windows分别保存最新快照，不累计无限历史。
- 显示器输入、USB归属和散热器档位均带`unknown/estimated/confirmed`语义。
- DDC写入成功不等于读回确认。
- 页面切换不改变业务状态。
- 网络断开不清除最后采样时间，但旧值必须标记过期且不参与温控。

## LVGL集成原则

- 复用已经验证的ILI9341 SPI初始化与方向设置，适配为LVGL显示刷新回调。
- 使用有限行缓冲或分块绘图缓冲，避免无依据地申请完整双帧缓冲。
- DMA能力内存和PSRAM用途在实机构建后按内存报告决定。
- LVGL tick、timer handler和刷新都在明确的单线程模型中运行。
- UI资源使用编译期数组或受控资源表，不在运行时无限分配。

## 安全原则

- GPIO7和GPIO8先写LOW再启用输出，外部10kΩ下拉保证复位期间释放。
- 继电器动作由有截止时间的状态机控制；UI崩溃或事件丢失不能无限吸合。
- 未知请求、错误协议、重复request_id和离线目标不得产生物理动作。
- Wi-Fi私密配置不写入版本目录。

## 编码约束入口

模块状态机、按键语义、页面字段、GPIO15背光规则以及所有禁止猜测的参数统一见`implementation_contract.md`。任何未确认参数只能集中配置或保留TODO，不能散落为魔法数字。
