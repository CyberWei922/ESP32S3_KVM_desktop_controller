# v0.5.0-dev.22 实现合同

本文是 `esp32/latest` 正式编码的总入口。它把已经确认的产品行为、UI、GPIO、安全边界和仍待实测的参数集中在一起。若本文与旧版实现冲突，以本文和 `StatsForKVM/PROTOCOL.md` 为准；`esp32/legacy/v0.4.0-dev.3` 只作为已验证底层能力的参考，不得整体复制。

## 1. 当前边界

- 目标芯片：ESP32-S3-N16R8。
- 工具链：ESP-IDF v6.1，开发期间不得擅自升级。
- 显示：ILI9341、SPI、320×240 横屏、无触摸。
- UI：LVGL、System 7 主风格、少量 System 1 黑白像素元素、纯英文。
- 网络协议：严格遵守 `../../../StatsForKVM/PROTOCOL.md` 的 protocol v1。
- 本目录包含当前正式开发 C 源码、测试和依赖声明；`build/`、`managed_components/` 与本机生成的 `sdkconfig` 仍属于开发环境产物，不纳入公开源码发布。

## 2. 固定 GPIO 与电气约束

| 功能 | GPIO | 固定行为 |
| --- | ---: | --- |
| 左键 | 4 | 内部上拉；松开 HIGH，按下接 GND 为 LOW |
| 中键 | 5 | 内部上拉；松开 HIGH，按下接 GND 为 LOW |
| 右键 | 6 | 内部上拉；松开 HIGH，按下接 GND 为 LOW |
| USB 共享器继电器 T1 | 7 | 输出；先写 LOW 再切输出；外接 10kΩ 下拉 |
| 散热器继电器 T1 | 8 | 输出；先写 LOW 再切输出；外接 10kΩ 下拉 |
| LCD DC | 9 | 显示驱动输出 |
| LCD CS | 10 | SPI 片选 |
| LCD MOSI | 11 | SPI 输出 |
| LCD SCLK | 12 | SPI 时钟 |
| LCD MISO | 13 | SPI 输入 |
| LCD RST | 14 | 显示复位输出 |
| LCD BLK | 15 | 只能开漏：LOW 熄灭，高阻释放点亮 |

背光方案已完成实机验证。ILI9341 的 `0x53` 软件命令在本屏幕模块上不能控制物理背光；禁止再把“画黑屏”或该命令当作关屏。GPIO15 不得推挽输出 HIGH。屏幕引脚 7 `BLK` 直连 GPIO15，实测拉向 GND 的电流约 0.2mA。

GPIO7/8 的继电器在启动、复位、烧录、异常和任务停止期间都必须保持释放。所有闭合动作必须有独立截止时间，不能依赖 UI 回调负责释放。

## 3. 三键语义

### 左键

- 单击：执行显示器输入与 USB 归属的联动切换。
- 双击：只交换 ESP32 内保存的“显示器目标”和“USB 推定归属”，用于二态校准；不得发送 DDC，也不得触发任一继电器。
- 左键长按与双主机显示待机联动，完整规则见`display_sleep_plan.md`：关闭GPIO15背光时并行请求Mac和Windows停止显示输出；再次长按时恢复背光并只唤醒关屏前的当前主机输出。
- 背光关闭后进入输入锁定，只保留左键长按；其余单击、双击、中键、右键事件全部丢弃且不得排队。
- 不让Mac或Windows整机睡眠；ESP32、Wi-Fi、WebSocket和遥测接收继续运行。

### 中键

- 单击：切换到下一页，页面顺序为 `SYSTEM` → `WEATHER` → `MARKETS`。
- 双击：切换到上一页。
- 长按：当前未分配，不得添加隐藏入口。
- 翻页只改变本地显示，不得修改 KVM、继电器、网络或温控状态。

### 右键

- 右键的散热器交互已进入第二阶段设计，完整规则见`cooler_control_spec.md`。
- Manual 模式：单击升档，双击降档。
- Standard、Silent、Turbo：单击提高目标温度`1°C`，双击降低`1°C`；dev.11临时范围为`20–70°C`。
- 按住 500–999ms 后松开切换下一模式；按住达到 1000ms 立即进入关机动作，松开时不得再切换模式。

按键驱动只产生语义事件。初始统一参数为：约 30ms 消抖、300ms 双击窗口、800ms 长按。为可靠区分左键单击与双击，左键单击须在双击窗口结束后执行。参数必须集中配置，不得散落在页面代码中。

## 4. KVM 联动状态机

左键单击只允许触发以下单一流程：

```text
空闲
→ 检查当前主机和目标主机的状态是否满足切换条件
→ 生成唯一 request_id
→ 命令当前画面所在主机执行目标输入的 DDC 写入
→ DDC 写失败或超时：结束，绝不切 USB
→ DDC 写成功：等待显示器完成换源
→ GPIO7 只产生一次 USB 继电器脉冲
→ 更新显示器目标与 USB 推定归属
→ 至少 5 秒冷却
→ 空闲
```

- X41Q 输入值固定为 DP=`7`、HDMI1=`5`、HDMI2=`6`。Mac 固定连接 HDMI2=`6`，Windows 固定连接 DP=`7`；HDMI1=`5` 当前不分配。
- X41Q 读回不可靠。必须区分 `write_succeeded`、`confirmed`、`estimated` 和失败，不能把写入成功显示成读回确认。
- 同一 `request_id` 的重试不得产生第二次继电器脉冲。
- 冷却期间忽略新切换请求且不排队；页面仍可切换。
- 重启、手工操作显示器或 USB 共享器后，本地状态只能标为未知或推定，不能伪装为已确认。
- GPIO7 USB继电器脉冲初值为 250ms，集中配置并允许在 200–300ms 范围内实机调整。DDC 成功后的等待时长及冷却起点仍待实测；不得自行发明数值。

## 5. 散热器与温控

- GPIO8 接口和安全默认 LOW 保留。正式实装必须遵守`cooler_control_spec.md`，不得从旧的首版占位规则推断行为。
- 四种模式为 Manual、Standard、Silent、Turbo；后三者默认目标值依次为 `40°C`、`50°C`、`28°C`。
- 自动控制必须包含温度平滑、升降档回差、最短档位保持时间、过热保护、推定档位和人工校准。
- Mac 离线、温度无效、数据过期或散热器档位未知时，暂停自动调档并在 UI 明示原因。
- 散热器只有离散档位。未知档位时只允许运行已定义的归一化校准流程，不得从未知状态直接计算升降档次数。
- 单击和双击的首轮测试参数分别为 `70ms`，以及 `70ms/80ms/70ms`；它们仍须实测后才能冻结。

## 6. 网络、协议与状态

- ESP32 是 WebSocket 服务器，Mac 和 Windows 是独立客户端。
- 每台设备只保留最新快照及接收时间，不保留无界历史。
- protocol v1 的 JSON 字段、2048-byte 上限、请求幂等、序号和错误语义以 `StatsForKVM/PROTOCOL.md` 为唯一协议依据。
- 顶栏 Internet 只代表 ESP32 已成功连接 Wi-Fi/局域网，不执行公网探测。
- 客户端连续 5 秒没有收到有效更新即标记离线；数据也按 5 秒阈值判定过期。
- 连接状态、数据新鲜度和指标有效性是不同状态：在线客户端也可能发送无效指标。
- 旧值可用于诊断显示，但不得参与温控。
- 未知协议版本、非法帧、错误目标、重复请求和离线目标不得触发物理动作。
- Wi-Fi 首版可以沿用当前 `KVM Config` 本地配置方式；首次配网入口可以后续增加。凭据不得写入源码、文档、版本归档或可分发二进制。

## 7. UI 页面与信息结构

固定顶栏采用 System 7 菜单栏外观，任何页面都显示：

- 当前页面英文名；
- Internet 状态；
- Mac 连接状态；
- Windows 连接状态。

状态不得只靠颜色，必须同时使用短文本或像素图标。`Online`、`Offline`、`Stale`、`Unknown`、`Switching`、`Cooling` 和 `Error` 要可区分。

当前使用三页仪表盘，不再采用“单一总界面内只轮换小窗口”的旧设计：

- `SYSTEM`：ESP32 IP、运行状态、数据来源、Mac/Windows连接状态和错误。
- `WEATHER`：当前天气、未来三天和未来五个整点。
- `MARKETS`：BTC/USDT、DOGE/USDT 和 USD/CNY。
- 顶栏在所有页面显示当前页面名、Internet、Mac 和 Windows 状态。
- 页面数据来自客户端发送的 `dashboard` 快照；ESP32 不直接访问互联网，只负责校验、缓存和显示。
- 中键单击切换下一页，双击切换上一页；页面切换不修改 KVM、网络或温控状态。
- 散热器区域显示实际档位、目标温度和模式，当前已连接 GPIO8 控制状态机。
- 屏幕底部不得绘制三个实体按键的功能说明，也不得出现与既定键义冲突的软按键。

## 8. LVGL 与并发规则

- 只有唯一 LVGL 任务可以调用 LVGL API。
- 网络、按键、KVM 和温控任务通过线程安全状态仓库与事件队列交互，不能直接绘图。
- UI 只展示状态和提交语义事件，不能阻塞执行 DDC、延时或继电器脉冲。
- 复用已验证的 ILI9341 初始化和方向设置，但按新版接口逐模块移植。
- 使用有限分块绘图缓冲；完整双缓冲、DMA 内存和 PSRAM 分配必须根据构建后的内存报告决定。
- 不允许高频重绘静态页面。只在状态变化或 LVGL 需要刷新时更新，避免验证固件中曾出现的持续动态重绘和看门狗问题。
- 所有任务必须可喂狗、可停止，继电器释放不受 UI 存活影响。

## 9. 视觉与资源规则

- System 7 是主体：灰阶、条纹标题栏、经典窗口、方形控件、像素图标。
- System 1 只用于少量高对比黑白元素；不混入 Mac OS 8/9 Platinum 风格。
- 屏幕只使用英文，不打包中文字库。
- 使用可分发开源字体与自制图标，不复制 Apple 专有字体、图标或系统资源。
- 动画只用于必要反馈，页面切换即时或极短；清晰度和稳定性优先。
- 物理关屏必须通过 GPIO15 熄灭背光；关屏后 UI 可停止无意义刷新，但业务任务继续。

## 10. 实机验收前必须确认或实测

以下事项没有答案时，只能保留配置项或 TODO，禁止实现者自行猜测：

1. DDC 写成功后等待多久再触发 USB 脉冲；5 秒冷却从 DDC 成功、USB脉冲开始还是流程完成时计时。
2. `KVM Config` 的正式文件名、位置、字段以及 ESP32 固定 IP 是否继续使用 `192.168.1.50`。
3. 散热器按钮最终时序、四档边界、断电记忆、校准方法、回差、最短保持和过热保护阈值。
4. Windows 客户端源码在独立 Windows 主机完成后，与 ESP32、macOS 进行 dashboard、KVM 和显示输出休眠/唤醒三端联调。

## 11. 首版验收底线

- 冷启动、复位、烧录和异常时 GPIO7/8 不误触发。
- GPIO15 重复关/开背光稳定，关闭后完全不发光，业务任务不中断。
- 三键手势无误触发、无重复动作；未分配手势完全无副作用。
- KVM 双向切换不少于 100 次；DDC 失败时 USB 零误切；重复结果不产生双脉冲。
- 在线、离线、过期、未知和恢复状态显示正确。
- SYSTEM、WEATHER、MARKETS 三页连续切换不少于 100 次，固定状态区、网络与遥测不中断。
- 散热器四模式、GPIO8继电器动作、上电校准和异常暂停策略通过实机验收。
- SYSTEM、WEATHER、MARKETS 三页连续切换不少于 100 次，网络与遥测不中断。
- dashboard 主备数据源、数据过期和恢复状态显示正确。
- 显示输出休眠/唤醒在 Mac、Windows 和 ESP32 三端完成联调。
- 完整系统连续运行至少 24 小时，无卡死、花屏、看门狗复位或持续内存下降。
