## 暂缓项：刷新同步背光补偿

状态：已写入`v0.5.0-dev.22`固件和macOS客户端，等待Windows客户端实现与三端实机验收。

### 已确认事实

- 厂商风格隔离测试固件已实机确认：GPIO15以20kHz PWM输出时，BLK能够呈现三个清晰亮度档位，说明本机实物支持通过BLK进行PWM亮度控制。
- 最精简的软件SPI测试在真实像素刷新瞬间仍会闪烁，因此问题不依赖LVGL、Wi-Fi或DMA；刷新期间的电气负载变化仍是待补偿对象。

### 临时参数（不是最终校准值）

- PWM频率：20kHz。
- 静态/非刷新亮度：60%占空比，暂时固定。
- 刷新期间亮度：初始验证可从100%占空比开始，最终值必须根据实机结果调整。
- 这些参数只能集中定义，禁止散落为魔法数字。

### 计划实现方式

- 在一次有效画面更新开始、首笔像素传输之前切换到“刷新亮度”。
- 在本次画面更新的最后一个刷新区块完成后恢复60%“静态亮度”。
- 不得在同一次LVGL更新的每个分块之间反复恢复60%，避免补偿本身产生闪烁。
- 背光开关状态优先级高于补偿：用户关闭背光后，任何刷新都不得重新点亮。

### 必须完成的刷新面积实测

刷新面积可能改变瞬时负载、传输持续时间和肉眼感受到的亮度下降，因此不能假设所有区块共用同一个补偿值。实施时至少分别记录：

1. 极小刷新：单个状态图标、短文本或中央小方块。
2. 中等刷新：一行Live Data、进度条或一个信息框。
3. 多分块刷新：同一UI状态变更触发多个区域连续传输。
4. 全屏刷新：开机页切换或完整界面重绘。

每组记录刷新像素数、总传输时长、静态占空比、刷新占空比以及肉眼结果（偏暗、持平或偏亮）。如果不同面积所需补偿明显不同，再决定采用：

- 单一固定刷新占空比；或
- 按刷新像素数/传输时长分为小、中、全屏三档补偿。

### 验收条件

- 小区域、中区域、多分块和全屏刷新时均无肉眼可见的变暗或过亮。
- 连续遥测刷新期间亮度稳定，PWM本身无可见闪烁或啸叫。
- 反复刷新不会破坏左键长按背光关闭与恢复功能。
